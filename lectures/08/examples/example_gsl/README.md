# GSL example

The program approximates the integral of `sin(x)` from zero to pi. It should
report a result close to **2**, together with an estimated absolute error.
It checks the GSL return status and releases its integration workspace.

## Build a local GSL installation (optional)

Download [GSL 2.8](https://ftp.gnu.org/gnu/gsl/gsl-2.8.tar.gz), then configure its source tree:

```bash
wget https://ftp.gnu.org/gnu/gsl/gsl-2.8.tar.gz
tar xzf gsl-2.8.tar.gz
cd gsl-2.8
./configure --enable-shared --enable-static --prefix="$HOME/.local/gsl"
make -j4
make install
```

Run the remaining commands from this example's directory,
`lectures/08/examples/example_gsl`.
Set the prefix to the installation you want to use:

```bash
gsl_prefix="$HOME/.local/gsl"
```

## Link the GSL archives

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic \
    -I"$gsl_prefix/include" example_gsl.cpp \
    "$gsl_prefix/lib/libgsl.a" "$gsl_prefix/lib/libgslcblas.a" \
    -lm -o main_gsl_static
./main_gsl_static
```

GSL and its supplied CBLAS implementation are linked from the archives.
The executable can still use shared system libraries, including the C++ runtime.

## Link the shared libraries

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic \
    -I"$gsl_prefix/include" example_gsl.cpp \
    -L"$gsl_prefix/lib" -lgsl -lgslcblas -lm -o main_gsl_shared

LD_LIBRARY_PATH="$gsl_prefix/lib" ./main_gsl_shared
LD_LIBRARY_PATH="$gsl_prefix/lib" ldd ./main_gsl_shared
```

`-L` selects libraries for the link step. `LD_LIBRARY_PATH` lets the loader find
that installation and its dependencies when the executable runs. Check the
paths printed by `ldd` to confirm which files are selected.

A runtime path can also be recorded while linking:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic \
    -I"$gsl_prefix/include" example_gsl.cpp \
    -L"$gsl_prefix/lib" -Wl,-rpath,"$gsl_prefix/lib" \
    -lgsl -lgslcblas -lm -o main_gsl_rpath
./main_gsl_rpath
ldd ./main_gsl_rpath
```

With the usual `RUNPATH` generated by this command, the recorded path applies
to the executable's direct dependencies. Dependencies of a shared library
must also be found, for example through their own runtime paths, the system
installation, or the `LD_LIBRARY_PATH` setting shown above.

## Use `pkg-config`

For an installation in a standard location, the flags can be obtained with:

```bash
pkg-config --cflags --libs gsl
```

For the local prefix, select its `.pc` file and compile:

```bash
export PKG_CONFIG_PATH="$gsl_prefix/lib/pkgconfig"
pkg-config --cflags --libs gsl

g++ -std=c++17 -Wall -Wextra -Wpedantic example_gsl.cpp \
    $(pkg-config --cflags --libs gsl) -o main_gsl_pkg
LD_LIBRARY_PATH="$gsl_prefix/lib" ./main_gsl_pkg
```

`PKG_CONFIG_PATH` locates build metadata. The runtime library search remains
separate. These commands use GSL's supplied CBLAS library; other compatible
CBLAS implementations, such as OpenBLAS, can be selected when needed.
